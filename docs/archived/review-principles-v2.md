## 一、总体判断

**概念主体已经成立，架构不需要推翻；上一轮 A 级五条已全部有实质处置，不是改名敷衍。但"原则层全部收敛"仍差最后一段：四处语义未定的地方，恰好是验收主张唯一外部证伪器（三份规则文件考卷）所依赖的东西。**

撑住这套设计的是六根柱子，与 v1 判断一致且本轮新增验证：

1. **两个不变量（无漏项/无添加）**，且本轮已诚实分层（条款级机械、断言级不设检验）；
2. **三级来源永不混层**，③级必须带前提+责任人——把 LLM 幻觉改造成可审计通道；
3. **锚 + 权威在文本那边**，库是可被文本反驳的下属物；
4. **快照隔离 + 案件自含 + 全局派生**（源码/编译产物类比成立）；
5. **词表出生单通道（全局、律师、经词表工具）+ 案内不造**——这条比 v1 时更硬，直接根除了"机器著作世界观"；
6. **合同节点 + 元规定**（§2.4）——v1 的 A1 被这个方案解掉，且改动比"规定类型学"更小，是漂亮的一手。

**结论：通过，但附三项动笔前补丁（甲、乙、丙）与六项建议补丁。** 甲、乙、丙不补，design.md 第一章写下的表结构会在验收阶段被迫返工；其余各项可在 design.md 对应章节内消化，只需现在挂账。

## 三、站得住的部分（本轮新增确认，只写 v1 没写的）

1. **§七 分流判据（归纳出生进词表、标准出生进工具配置）** 是一条可复用的治理原则，且顺手解决了"单位表要不要走两遍两闸"的伪问题。建议它在 design.md 里升格为与两个不变量并列的显式判据。
2. **§六 文本为源、SQLite 为快照** 的取舍论证完整（人审/git/协作/长寿 vs "难手改是弱保护，真门卫是加载校验"），这是对的工程判断。
3. **§2.2 "交易角色与关系性质分清"**（买方/卖方是主体识别层，义务人/行使方是当事人引用层）——这一刀切得准，直接消灭了"角色的受控词表"这个伪需求（v1 的 A4 有一半死在这里）。
4. **§5.3 吸并三条硬线**（换当事人对/换模态/条件槽成堆）配"槽描述一条边，挂不上第二个当事人"的解释，是把类型系统陷阱写成可执行判据的少数成功样例。
5. **§2.4 三个"便宜"**（主语判据推广、作用域=位置隐式、复用单主语记录模式）是对 v1 A1 的最小改动解，避免了引入一整套作用域边机制。
6. **§8.2 范本下划线=槽声明、空白=槽识别正确输出** 及其副产品（爱编值的提取器当场露馅）——这是概念设计里少见的"免费测试"，价值真实。
7. **§四 锚表"任何加速手段不入概念设计"**——概念与实现的边界自觉，这在本类项目里是稀缺品质。

## 四、必修项（动笔 design.md 前应给出裁决）

### 甲、"取代"与"当前规定"的语义未定，而验收主张压在它上面（最严重，但也最廉价）

**证据**：§一 承诺"本底座不提供跨合同数据查询"，§一 对消费方的承诺是"三份规则文件的每条检查项都必须能表达为本模型上的查询"；§2.3 说消费方算"当前规定"时被活动修改链指向的记录不算数；§八 8.3-6 说"修改链与重定向在查询时折叠"。但全文没有任何地方定义：

- "当前规定"是相对**什么坐标**取的投影？（全部文本的并集？每个素材的最新版本？某个时点子集？）
- 修改链折叠是传递闭包吗？多条链竞争同一被取代记录时怎么办？链成环怎么办？
- 无修改链的并存记录 = 冲突，与"被修改链取代"的记录，在同一个查询里如何区分呈现？

**为什么不补会返工**：考卷要求"只准查库作答"。同一道检查项，取"并集投影"与取"最新版本投影"会给出不同答案，因此考卷**不可判分**，而考卷是本项目唯一的系统性质量度量。更麻烦的是"冲突并存"是风险，而"被取代"不是风险——两者在查询输出里必须可区分，否则冲突展示的承诺（§3.1、§一）失效。

**最小补丁**：在 §一 的边界声明与接口章各加一段**投影语义**（不必新增字段，纯语义规定）：
① 定义"当前规定"= 对每个素材取最新文本版本，沿修改链取未被指向者的不动点；
② 定义"冲突"= 同一（主体组、模态、行为类）下无链相连且互不相容的多条记录；
③ 声明投影的**唯一性**要求：同一案件上，两个合规实现必须给出同一投影（这正是可判分的前提）。

### 乙、多文档案件里"当前文本"无实现路径，"读库即读合同"会退化为"读库即读旧合同"

**证据**：§一 "时序边界"说原生时序是"文本的序列——版本先后、修改链、登记序"；§四 素材表/文本版本表只有素材名、类型、哈希、快照、版本号；§2.3 只承认取代（条款级修改边）。于是一个真实场景无法判定：主合同有第 5.3 条，补充协议有第 5.3 条但**未写"取代"字样**，且补充协议本身也无附件优先条款。此时库里两条并存，投影只能报冲突；而人类的"当前规定"是补充协议那条。

这不必然是缺陷（未写取代就是文本没规定，报冲突是忠实的）——**但它必须在概念层说清是"有意为之"还是"尚未想到"**，因为它决定消费方拿到的答案是"冲突，请人工裁决"还是"当前规定=X"。同时暴露一处文档内部不一致：

**§2.3 只承认"两类支撑节点"（事件、定义事实），§四 节点表却是五类（主体/事件/定义值/外部基准/合同）。** 主体、外部基准、合同三类节点在 §二 从未出场。这不是排版疏忽：它说明"节点"这一层在概念设计里没有成节的定位，而 §2.4 的合同节点与 §3.3 的出处机制都建在它上面。

**最小补丁**：① 在 §2.3 或新增 §2.6 给出五类节点的统一叙述（谁引入、为何是支撑节点）；② 明写多文档序：素材登记顺序是否即文本顺序、补充协议取代整条时是否需要"整条取代"的修改边、未写取代时的呈现规则；③ 若答案为"登记序即文本序"，则在 §四 素材表给该序一个落点（现在没有）。

### 丙、指向机制双轨：同一语义可落在两处，会直接变成 design.md 的表结构争吵

**证据**：
- §2.2 值形态含**引用**："指针，指向素材/附件/术语定义/定义值"；
- §2.2 条件的叶"指向事件/单据/期限/量"；
- §四 引用表装"条件、触发、算式引用、修改、别名声明、同一性、解释性指向"。

于是三处重叠：① 算式引用定义值，既是细节行的"引用"值，又是引用表的一行；② 条件叶指向的事件，是值内指针还是引用表的行；③ "规格见附件A"是细节值还是引用表的解释性指向。**同一语义有两个合法存放位置 = 入库时的自由裁量 + 查询要扫两个位置 + 对账无法在一个位置闭合。**

**最小补丁**（一句话原则即可，不必改结构）：**规定一条**——指针若属于某个槽值的内部结构（算式、条件叶、重复组），随值内联存储、不建引用行；引用表只存"连接两条规定/节点"的语义边（修改、别名声明、同一性、解释性指向）。再补一句附件指针的归属（我倾向"素材级指针内联在值里"，但这是作者决定）。这条不定，工作清单①（表结构与来源级字段方案）就没有唯一解。

### 丁、验收主张缺排除判据与分档，"每条检查项可表达为查询"目前不可判

**证据**：§一 的承诺 + §九 的考卷（三档：可答且对/可答但错/不可答）。但三份规则文件的检查项里天然混着三类：

1. **事实型**（"预付款比例是多少""有无迟延交付违约金条款"）→ 本模型可答；
2. **对照型**（"违约金是否超过合同总价 20%"）→ 上限若规定在合同里，模型提供值，裁决在消费者；
3. **评价/效力型**（"该条是否与法律强制性规定冲突""是否显失公平"）→ 按 §一 边界根本不属建模层。

现在没有分档规则，于是① 评价型项会被记为"不可答" → 大量缺口 → 貌似词表失败，实则题目出界；② 更糟的是反向作弊：任何**任何**答不出的题都能以"词表缺口"入缺口表（§八 8.3-4"装不下的规定点不硬塞，当场写入缺口表"），于是"零容忍的机械六查"照过，考卷却毫无约束力。

**最小补丁**：在 §一 承诺旁加两句话：
① **分档判据**：检查项含外部阈值或效力判断者不计数；对照型计为"模型供值 + 消费方裁决"两步，两步都写明才计通过；
② **及格线**：考卷同时报两个数——表达力（正确表达为查询的检查项占比）与缺口基线（每百条条款的缺口记录数与缺口类型分布），后者不得只报总数。

这两句加上，考卷才从"活动"变成"可判的验收"。

## 五、建议补丁（不至于返工，但建议现在挂账并进工作清单）

1. **补"提取章"**。工作清单七项（存表面、锚细则、追加vs可变、主体识别、查询接口、yaml schema、六查算法）里没有提取——而验收（机器独跑）与全部日常产出都靠它，资产排序又把它排最低。建议加：遍次结构、多文本版本下"提取跑哪一版"与旧记录重提取的关系、表格/清单附件如何提取、锚生成规则（含单元格）。
2. **把"表格/清单附件的锚"写进锚细则**。价格表、规格表、工程量清单既是量值主要来源，又是字符覆盖与条款切分的失效场景。锚表目前是"引文＋条款地址（素材/版本/条款）"，无单元格级地址。这是 v1 的 C10，仍未处置，且它与必修项②（多文档序）同属锚地址方案的边界。
3. **案件自含把"提取器"也记上**。§一 说"读库即读合同"、§六 说"案件放多少年自己解释自己"，但提取是 LLM（资产排序里最短命），出身表只记词表/格式/单位版本与哈希，不记提取批次的模型与批次号。③级指称绑定要求提取器署名（§八 8.3-4），说明这个信息是存在的、只是没统一入账。建议：出身表加"提取批次"（模型/版本/时间），或明写从 ③ 级署名处回溯即可、无需统一字段。
4. **补"协调规定"的落点**（v1 B4 残余）。pre-design 说"多方关系降解为多条二元边 + 一条协调规定"，但引用表七类里没有协调 / 关联边。低频（连带责任）但属结构面。
5. **"归类归属"的来源级归属需澄清，并补数据校验**。§3.2 承认"归类归属是解释，无机械来头"，但 §3.2 表格的"例"把"值='收到预付款后30日内'"放在①级——那条确实有锚；而"这条讲的是付款时点、该归付款单元"是解释主张。建议在 §3.3 明写归类归属的来源级（③级带前提+责任人？），否则"解释永久漂移"。**另需一条机械校验**（目前未见）：**同一主体 id 在同一案件内的规范形/统一社会信用代码必须唯一**——这是"比 id 相等"能成立的前提；否则两个 id 指向同一社会信用代码时，"宁可分裂不可错并"会把错并变成静默分裂。这是我最想问作者的一条。
6. **交付物缺"投影与查询语义规范"**（v1 B7 未处置）。契约层已经定了（投影计算归消费方），但投影语义需由底座规定（见必修项甲）。可只是定义文档，不含实现。
7. **锚机制的现成范式对照一句即可**（v1 C9）。"引文＋条款地址"作为概念表示法已足够；但既然 §十一 已借 Concerto 的格式契约串，建议同类地补一句对照 W3C Web Annotation Selector / standoff annotation，避免将来重造。
8. **修改后的多出处行与"行级单锚"的假设**。§2.3 的承袭机制下，一条新记录可能同时带"补充协议的锚（改动槽）"与"原合同的锚（承袭槽）"。锚表可被任何行引用，所以多锚在存储上可行，但"每条记录能翻回原文"的叙述默认了单锚。建议在锚细则里明写：行级多锚合法，且承袭槽的锚必须保持指向原始规定处。
9. **"不得"在模态表里无定义**（小而硬）。§2.2 的映射表是"须/应当→义务；有权→权力；可以→许可；不承担、免于→豁免"，**没有"不得/禁止"**；而 §8.1 的读手五样明列"模态词（须/有权/不得）"。不得转让/不得分包/不得转租是采购与工程合同的高频条款。两种解法：或补"不作为义务"模态（则核心地位表要加一对），或裁决它归入义务且对向方**允许缺席**（这直接动了"每条关系恰好一个核心方"的判据）——所以它是概念选择，不是措辞。顺带：权力/许可的触发与条件目前只能落在"时"槽与条件值里，"买方有权解除，但须在 30 日内书面通知"这类条款的落点建议在 §2.2 明确一句。

## 七、对验收主张的两条补强（与必修项丁配套）

1. **表达力（考卷）** 与 **提取质量（缺口基线 + 零容忍四查）** 是两个方向，目前 §九 的四步（六查 / 考卷 / 报告 / 复跑对比）已经朝这个方向走了，只差把两个数字**分开报**。建议报告固定两栏：
   - 表达力：可答且对 / 可答但错 / 不可答 的三档分布，且"不可答"必须归因（词表缺口 or 出界题）；
   - 提取：四查通过率、缺口率、缺口类型分布。
2. **考卷语料的代表性**（v1 C3 残余）：考卷=中国法采购×2 + FIDIC，全在采购族，与 §8.2 "跨种类"的词表归纳前提不对称；建议另配非采购类检查项（服务、股权、租赁各若干），否则"验收通过"只证明了一个种类。

## 八、最终结论

- **方向与概念主体：通过。** 上一轮 A 级五条已实质闭合，B 级大半闭合，处置质量可信；两个不变量、三级来源、锚与快照隔离、词表单通道出生、合同节点与元规定这五件是这套设计的承重件，未见动摇理由。
- **"原则层全部收敛、待决为零"这一结论应修正为"待决三项 + 挂账六项"**：甲（取代/当前规定/冲突的投影语义）、乙（多文档序与节点层统一叙述）、丙（指向机制单一落点原则）为必修；§五 九条为建议。
- 三项必修的共同点值得指出：**它们都落在"库→消费方"的那条边上，而不在"文本→库"这一边。** 这套概念设计在"如何忠实地把合同搬进库"上已经相当扎实（甚至过度谨慎，这是优点）；欠的是"库如何自解释地交出去"——而验收主张恰恰全部压在后者上。
- **确信度**：
  - 甲、丙、丁与 §六 全部条目：基于两份文档逐句核对，确信度高；
  - 乙中"多文档序无落点"：确证（§四 素材表/文本版本表无此字段）；"是否为有意为之"需作者确认；
  - §五 5（同 id 规范形唯一性校验）：需作者确认是否已在别处隐含；
  - 本评审不涉及实现、性能、成本与"项目是否值得做"；考卷所依据的三份规则文件不在仓库内（`legal/src/` 为空），故"检查项能否表达为查询"这一点我无法实证，只能评估其判据是否可判——结论是**目前不可判**（必修项丁）。
