# principles.md 概念设计 — 独立第三方评审

> 评审对象：`legal/docs/principles.md`（含 `pre-design.md` 作为讨论轨迹与判据来源）
> 评审日期：2026-09-11　评审人：独立第三方（未参与者）
> 评审标准：①概念自洽（内部无矛盾）；②概念完备（声明的不变量在本体与存储面有承载）；③边界诚实（承诺与机制匹配）；④可验收（验收主张可判定）；⑤风险可控（最高价值/最高风险件有落点）
> 未评审：实现细节、性能、成本、人员与排期。评审时 `legal/src/` 为空，无代码可对照。

## 一、总体判断

**方向不需要推翻，主体是扎实的；但"原则层全部收敛、待决为零"这个结论仍不成立。**

撑住这个设计的是四根柱子，都是对的：两个不变量（无漏项 / 无添加）、三级来源永不混层、锚 + 快照隔离 + 案件自含、以及"词表管形制、账本管值、律师治词表"。尤其是把 LLM 的不确定性逼进"③级显式推断必须带前提与责任人"这一条通道，以及"外部基准只记被引用、永不记数值"——这两条是很成熟的工程决定，很多同类项目都栽在这里。

但本轮评审发现三处**概念层空白**（不是 design.md 的日常字段工作，而是动笔前该定的东西）：

1. **模型只承认"二元关系"一种规定形态，接不住元规定**（解释规则、优先次序、除外、免责、合同级生效/终止条件、定义条款、完整协议、可分割性）。文中把解释规则塞进"合同文件构成类单元"，而该单元过不了它自己的单元三资格。
2. **受控词表只有两层，模型实际依赖至少四层**（角色、事件/谓词、外部基准、单位），而"唯一需要治理的部分"这个断言建立在"只有 unit/slot 是开放的"之上。
3. **完备性不变量在存储面无载体**（"归类"没有表也没有字段），而"字符覆盖"证明不了"断言被归类"。

另有一处**架构承诺与机制不匹配**：`§一` 说合同群是"同一张图多几份素材"，`§四` 说"一个案件 = 一个 SQLite 文件 = 一份合同或一个交易"；两者只在"一个交易内部"相容。围绕一个主体的跨交易合同是多个文件，而全套命令里唯一的跨案命令（聚合）只管词表。数据级跨案查询没有设计路径——这不是"工程量"，是缺一个组件。

以及一批内部矛盾与过度声称（见 §四、§五），其中最尖锐的一条：`§三` 承诺"消费者可以只信任某一级（只消费①②级机械验证过的行）"，但**归类主张（"这段是付款时点"）在三级里没有任何一级**——它既非原文引述、也非机械变换、通常也无署名。过滤来源级过滤不掉解释性。

**结论：有条件通过。** 概念主体可作为 design.md 的地基，但 design.md 第一章除已列的四件前置欠账外，应再加三件：元规定类型学与作用域机制、受控词表归位、跨案边界声明（或最小跨案层）。

## 二、站得住的部分（具体，非客套）

| # | 决定 | 为什么对 |
|---|---|---|
| 1 | 两个不变量选"完备 / 忠实" | 这个品类最容易被"抽得挺全"和"抽得挺像"糊过去；把质量定义钉在两个可对账的方向上，是后续一切审计的前提 |
| 2 | 三级来源永不混层 + ③级带前提与责任人 | 把 LLM 的幻觉从"风险"改造成"带署名的可审计通道"，这是能落地的处理方式 |
| 3 | 锚 + 权威在文本那边（库是可被文本反驳的下属物） | 立场明确，且"锚必须机械可验"给出了可执行的判据，避免了"结构化库成为新权威"这一常见腐化 |
| 4 | 快照隔离 + 案件自含 + 全局派生 | 源码/编译产物的类比成立；"旧案放多少年自己解释自己"这一条在长期资产口径下是正确取舍 |
| 5 | 条目不可变、以增删代替修改、取代关系显式 | 术语协调（ISO 704 传统）的现成规程，搬运正确，避免了"一个 id 两个含义"的漂移 |
| 6 | 吸并优先 + 三条硬线 + 裂变补谱系 | 把"用 if-else 重造类型系统"这个经典陷阱写成了可执行判据；"槽是耗材，单元是观点"的代价不对称分析也对 |
| 7 | 外部基准只记被引用、永不记数值 | 避免汇率/利率/指导价腐化；把"事实"与"参数"分开，少见而正确 |
| 8 | 不裁决铁律 + 冲突并存即风险点 | 把裁决从底座剥离是对的能力边界；"不裁决"同时保护了忠实性 |
| 9 | 值与表层形分离 + 格式契约串 + 往返验证 | 归一化可逆可查，值枚举 diff 才有意义 |
| 10 | 范本空槽作为免费的无添加测试 | 一个漂亮的副产品：爱编值的提取器在范本上当场露馅 |

## 三、A 级：概念层空白（应在 design.md 第一章解决）

### A1　只承认一种规定形态，接不住元规定（最严重）

现有原子式是 `（负担方，受益方；性质；行为类；细节{槽:值}）`，扩展只有"修改链"和"引用表"。但合同文本里有一大类规定**不构成二元关系，或作用于其他规定**：

- **解释规则**：附件与正文不一致以正文为准、中英文不一致以中文为准、条款标题不影响解释
- **文件构成 / 完整协议**：下列文件构成合同整体、本协议取代此前一切约定
- **除外 / 但书**：作为付款条件，但不作为质量最终依据（需同时指向两条不同的效果）
- **免责 / 通用救济**：不可抗力免责、任何一方违约应赔偿对方损失（作用域=全部义务）
- **合同级条件与期限**：本合同自甲方取得××批准后生效、本合同有效期、终止事由
- **定义条款**：本合同所称"设备"包括主机及附件（`§2.3` 只给了"合同总价=××"这类**数值**定义事实，文本型术语定义是解释其他一切条款的底座，却无位置）
- **可分割性、份数、通知送达、转让限制、语言版本**

文中对其中一类的处理是："'附件与正文不一致以正文为准'这类优先次序条款不是修改——它是解释规则，照常作为普通规定入库（**归属合同文件构成类单元**）"。这句话自相矛盾：`§五` 的单元判据是"'谁对谁有一个X'问得出口的是单元"，而"谁对谁有一个合同文件构成"问不出口。**用一个不满足自家单元资格的单元来接一类规定，正是原子式覆盖不足的证据。**

连带的两个后果：

- `§2.3` "规定与规定之间只有一种连接动词：修改"站不住：**取代只是"作用域"的一种**。优先、除外、免责、生效条件都是对别的规定划作用域的动词。模型缺的不是一个动词，是"作用域"这个维度。
- `§2.2` 把"除外"列为五种**值形态**之一，是把作用域限定语塞进了一个槽位。但书的语义是"这条效果不适用于那种情形"，必须指向被排除的对象（上例中同时指向"付款条件"与"质量最终依据"两条效果）。所以 pre-design 里"但书双重身份由'槽声明值形态=除外'自动消解"是**改名而非消解**。

**建议**：引入上位概念"规定"，把"关系"降为规定的一种形态；另立元规定类别 + 作用域边（作用于哪些关系/规定）。这是把 `§2.1` 的原子式从"关系模型"升级为"规定模型"的最小改动。

### A2　完备性不变量在存储面无载体；"归类全覆盖"不等于"无漏项"

- `§3.1` 与 `§8.3-4` 都要求"每个信息点必有归类"，"无规定内容段落记'无规定内容'归类"。
- `§四` 的表清单（关系图五件套 + 证据流程五件）里，条款表字段是"素材/版本/序号/起止偏移/文本"——**没有归类列，也没有归类表**。
- 于是 `§3.1` 的"完备性由归类全覆盖直接满足，由对账的字符覆盖与值枚举复查"是过度声称：字符覆盖只能证明"全部字符都在条款表里"（`§8.3-3`），证明不了"每个断言都被归类"。

更实质的一层：**"信息点"没有粒度定义**。一个条款含三个关系（`§2.1` 的例句正是如此：基础义务 + 解除权 + 赔偿义务），提取器只归一个，条款仍算"已归类"。所以目前的机制允许"漏项"与"全归类"同时成立。这是"语义完备性不可机械判定"的又一次现身——只是换到了断言层。

**建议（廉价且能变成真账）**：①条款表加"归类"字段（或建归类表），指向关系/细节/节点/引用/"无规定内容"；②对账的机械账从四项升为五项，加**归类覆盖双向查**：每条条款至少一条归类记录（正向），每条关系/细节行至少被一条条款归类覆盖（反向）。这样不变量就从声明变成了账。

### A3　值形态表声称封闭却不封闭；条件算子不足

`§2.2` 说"值只有五种基本形态，封闭、写死程序"。但：

| 缺项 | 证据 | 后果 |
|---|---|---|
| 名/文本、枚举、引用（附件、单据、图纸） | `§5.3` 通用槽池含"**地点**/方式"；`§2.1` 例中"设备"需指向规格附件 | 交货地点=上海港、以书面方式、规格见附件A 无处安放；`细节表` 却要求每行有"值形态" |
| 条件算子只有"并列、且" | `§2.2` 条件行写"（并列、且）" | `§2.1` 自己的例句"迟交**超过**4周"就需要比较+阈值；另有 或、非、计数（连续两次验收不合格） |
| 单位未受控 | `§2.2` 量=数值+单位 | 万元/USD/%/工作日/月 由谁治理？值枚举 diff 与跨案比较都依赖它 |
| "除外"错位 | `§2.2` | 见 A1：它是作用域限定语，不是值形态 |

值形态封闭在代码里，而单子本身不封闭 = 每遇到一个新形态就要改代码，这与"换行业换律所，工具一字不动"直接冲突（`§七`）。

### A4　受控词表只承认两层，模型实际依赖四到六层

`§5.2` 断言："行为类与槽条目：开放，律师治理——**唯一需要治理管道的部分**"。但：

- **角色表**：`§2.2` 说"角色（买方/卖方/担保人/银行）是边上的属性"——不受治理。现实中同一角色叫 买方/甲方/需方/业主/雇主(Employer)/订约方。跨案查询"该供应商的交付义务"离不开角色规范化。
- **事件/谓词表**：`§2.3` 让条件、相对时点、触发**全部指向事件**，而事件的类（交付完成/验收通过/付款到账/违约发生/保函开立）不在任何词表里。自由文本则跨案查不了"所有以'验收通过'为触发的权力"；受控则需与 unit 同级治理。
- **外部基准表**：`§四` 决定"只记被引用、永不记数值"（对），但基准清单本身是受控词表（LPR/一年期LPR/贷款市场报价利率；汇率要指明货币对与来源；工作日历要指明地区）。它目前无治理位置。
- **单位表**：见 A3。

这直接冲击验收主张：`§一` 的考卷是"三份规则文件的每条检查项都能表达为查询"，而检查项考的正是跨文本的一致命名。**"唯一需要治理的部分"应改为"两层开放（unit/slot）+ 若干受控清单（角色、事件类、外部基准、单位）"，并各自给出治理节奏（单元深审、其余快审）。**

另有一处相关的封闭性漏洞：`§四` 出身表只记"加载的词表文件名+内容哈希"。**模态表与值形态表写死在代码里，不进案件**——那么"案件放多少年自己解释自己"依赖的是**工具版本**，而工具版本没有进案件出身。将来值形态增补一条，旧案数据的解释随之改变。建议：出身表加"封闭表版本/哈希 + 快照格式版本"。

### A5　跨案层缺位：承诺与机制不匹配

- `§一`：合同群"= 同一张图多几份素材，零新增本体机制；**唯一新增工程量是跨文本的节点同一性**"。
- `§四`：**"一个案件 = 一个 SQLite 文件 = 一份合同或一个交易的全部文档"**。

两者只在"一个案件=一个交易（可含多份合同）"的读法下相容。围绕一个主体的跨交易、跨年份合同是**多个文件**，此时不存在"同一张图"。而：

- `§七` 与 `§8.3-6` 里唯一的跨案命令是**聚合**，且只对词表出报告；数据级跨案查询无设计路径。
- "唯一新增工程量是跨文本的节点同一性"把问题降级成工程量。跨文件的实体同一需要**组件**：全局主体键（统一社会信用代码是现成的键）、索引/注册表、查询路由。这些都不能靠"多拷几份素材"得到。
- **案件边界判据本身也未定**：哪些文档属同一案件（附件？往来函件？未签署版本？第三方担保合同？中标通知书？）。它决定锚、修改链与同一性的作用域。

**建议二选一**（不能含糊过去，否则实现期会被迫临时发明）：
① 补最小跨案层（全局主体键 + 跨案索引 + 查询路由；不进本体，只做寻址）；
② 在 `§一` 显式写死边界："本底座不提供跨案数据查询，跨案只在词表层聚合"，并把"对商业世界的法律关系做精细化建模"降级为"对单份/单宗交易的合同文本做关系级建模"（或保留口号但注明它是本体层主张，不含实例层）。

顺带：资产排序里"实例库"排第三；实例不能跨案聚合，其长期价值进一步受限，而"底座"叙事默认了它可聚合。两者需要一个一致的说法。

## 四、B 级：结构裂缝（设计章内可化解，但概念表述需改）

**B1　原子式字段名只对义务成立，Hohfeld 只写了义务的读法。**
`§2.2` 与 `§四` 都用"负担方/受益方"，而模态四值含权力/许可/豁免。"买方有权解除"里权力持有者是买方；被解除一方承受的是 Hohfeld 的 **liability（承受）**，不是 duty；豁免更极端——没有负担方。文中"存一条边、两面读"只举了义务一例。建议：字段改模态中性（持有方/相对方），并给出四模态读写表（义务→claim-right、权力→liability、许可→no-right、豁免→disability）。另：**"权利"不在模态表里**，"买方享有哪些权利"这类检查项必须在查询编译层合成（对方义务的反向读 + 本方权力 + 本方许可）——这层规则是验收主张的承重件，应写进接口章。

**B2　修改链只支持整条取代，与忠实性不变量相撞。**
`§2.3`："旧记录一个字不改，消费方算'当前规定'时被活动修改链指向的记录不算数"。槽级修改（"第5.3条中'30日'改为'60日'"）下，旧记录里未被修改的其他槽（如"以验收合格为前提"）也随之不算数 → 投影丢信息。要保住它们只能生成**合成行**，而合成行不存在于任何单一跨度，其出处只能是 ③级（前提+责任人）——与 `§3.2` "永不混层"的干净叙述冲突。不生成则合并算法落到消费方（见 B7）。另：补充协议"新增第5.4条"无旧记录可指，修改链表达不了"引入"，只能靠锚的版本，应明确区分"引入"与"取代"。建议：修改边做成三元 `(新记录, 旧记录, 作用域=整条|槽清单)`，并在概念层定义投影语义。

**B3　三级来源覆盖不了"归类"这一主张，"按级过滤"的承诺不成立。**
槽归类、单元归类、事件指认：句子没说"这是付款时点"（非引述）、没有格式契约（非机械变换）、通常无署名（非③级）。但 `§3.2` 承诺"消费者可以只信任某一级（例如只消费①②级机械验证过的行）"——**来源级过滤不掉解释性**。
**建议（材料已有，只差接线）**：`§8.1-4` 收割"真实措辞例句（顺手长成识别特征）"、`§十一` LU↔识别特征——把归类主张的来头定义为"命中单元X的识别特征#k（带锚例句）"。归类立刻可审计，识别特征的命中/误判率也变成可统计的词表治理指标。

**B4　正文声称的两类边没有存储落点。**
① `§一` "原生时序 = 文本序列（版本先后、修改链、登记序），一个偏序（家谱）"——`§四` 引用表六类是 条件/触发/算式引用/修改/别名声明/同一性，**没有"版本先后"边**；素材表与文本版本表只有版本号（登记序=加载顺序，操作者产物，不是文本序）。② `§2.2` "多方关系降解为多条二元边**加一条协调规定**"——引用表无协调/关联边。建议引用表补这两类。

**B5　③级要求的"责任人"无字段。**
`§3.2` 要求③级"必然伴随 前提 + 责任人"；`§四` 关系表与细节表的列里只有"来源级、出处（锚或前提引用）"。③级是唯一人工通道，署名不落库等于纪律靠自觉。

**B6　"签署栏 = 无规定内容"与存储面自相矛盾。**
`§3.1` 把"页眉、签署栏"举为"无规定内容"的例子；但 `§四` 要求主体节点记"规范形（全称+统一社会信用代码）"，而规范形与角色绑定恰恰来自首部/签署栏/营业执照；签署人代表权与盖章在法律上是要紧事实。同时 `§3.3` 要求"主体对"有来头，`§四` 却只给"事件与定义值记出生锚"——**主体无边、角色（边属性）无边**。工作清单④（主体与事件的出处锚定与同一性判据）正好建在这个缺位上。建议：主体节点与角色绑定各补出处，并把"签署栏"从"无规定内容"的例子里移出（换成页眉/页码/目录）。

**B7　资产排序与交付物错配：代数没有交付物，而验收全压在代数上。**
`§一`：本体 > 代数（查询/diff/聚合）> 实例库 > 提取管道。`§十` 交付六件：两个 CLI + 四个 skill——本体的**机制**交付了（初始化/词表 CLI），实例库的机制交付了（案件 CLI），**代数无交付物**（`§附⑤` 还把投影类计算整体划给消费方）。而验收主张（"每条检查项都能表达为查询"）与方法（"词表改进后复跑对比基线"）都建立在查询语义之上，没有规范就无法判定、也无法回归。建议：交付《投影与查询语义规范》（检索式查询规范形式、四模态读法、修改链与重定向折叠、冲突并存的呈现约定、"当前规定"参考视图的定义）——可以只是定义，不含实现。

**B8　案内机器新建 + 条目不可变 + 快照不动 = 近义单元永久固化且不可归并。**
`§5.4` 允许提取器当场新建单元条目，同时条目不可变、旧案快照只增不动，而"单元错的代价是系统性的（碎片化拆散查询）"。于是一个由机器发明、后来被认定是"X 的另一说法"的条目永久留在旧案，跨案按单元聚合把它算成两类。词表只有"取代了谁"（代际对齐）与裂变"原属"（谱系），**没有条目级的"等价/归并"关系**（A≈B 并存，而非取代）。且 pre-design 2026-09-11 把"单元出生带证据包走全局评审"整条废除，出生门槛从"事前带证据"变成"事后低频扫全部案件"——代价不对称。
**建议（低成本）**：案内自动新建时自动附最小证据包——(a) 触发新建的锚，(b) 最相近既有条目 top-k 及相似依据（识别特征重叠），(c) 提出者（模型+版本）。聚合审查从"回忆题"变"选择题"（正是 `§8.1` 闸一的理由），并为将来的归并关系留好数据。

## 七、若我主刀：最小改动清单（按序）

1. **加"规定类型学"与作用域机制**（A1）：关系降为规定的一种形态；另立元规定（解释规则/优先/除外/免责/生效条件/定义条款/合同级条件）+ 作用域边。
2. **给不变量配载体**（A2）：条款表加归类列（或归类表）；对账加第五查"归类覆盖（双向）"。
3. **值形态补全与归位**（A3）：补 名/文本、引用、枚举、地点；条件算子补 或/非/比较/计数；单位与基准清单归位；"除外"移出值形态。
4. **受控词表归位**（A4）：两层开放（unit/slot）+ 四类受控（角色、事件类、外部基准、单位），各自标明治理节奏；出身表加封闭表版本与快照格式版本。
5. **跨案层二选一**（A5）：补最小跨案层，或显式写死边界并降级口号；同时补"案件边界判据"。
6. **原子式字段模态中性化 + 四模态读写表 + 权利查询的编译规则**（B1），入接口章。
7. **三级来源接上归类出处与责任人字段**（B3/B5）；签署栏/首部移出"无规定内容"并补主体与角色的出处（B6）。
8. **引用表补 版本先后 与 协调 两类边；修改边支持槽级作用域并定义投影语义**（B2/B4）。
9. **交付物加《投影与查询语义规范》**（B7）；把"追加式 vs 可变库"从"纯实现选择"升为"接口语义"（C6）。
10. **案内自动新建附最小证据包**（B8）。
11. **design.md 工作清单加两章**：提取章（C4）、元规定与作用域章（A1）；验收主张加排除判据（C8）。

## 八、评审确信度与局限

- 结论基于两份文档的文本证据；`legal/src/` 为空，无实现可对照，因此所有判断都是**概念层**判断。
- 我可能误判的三处，需要作者确认：①"归类"是否已隐含在条款表某字段的设计意图里（文中未写）；②"事件类/角色"是否打算并入"行为类（单元）"这一层词表（若如此，A4 的分量下降，但仍需在 `§五` 明说，因为单元资格与事件谓词的判据不同）；③跨案层是否在你的规划里属"将来的租户"，若是，则 A5 只需把边界写成明文，而不必现在补组件。
- 本评审不涉及排期、成本与人力；也不评价"是否值得做这个项目"——只评价这套概念设计是否自洽、完备、可验收。

## 九、一句话结论

**概念主体（两个不变量、三级来源、锚与快照隔离、词表治理、吸并硬线、外部基准不记值、不裁决）质量高，方向不必推翻；但"待决为零、原则层全部收敛"应修正为"待决三件"——元规定与作用域、受控词表归位、跨案边界声明。补齐这三件后，design.md 的地基是可靠的。**
