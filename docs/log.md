# 日志

## 2026-09-09

- 调查 Accord Project（Linux Foundation 开源智能法律合同技术栈，68 仓库），为合同结构化工具找参照系
- 与 cogengine（案件事实引擎）对比，认定本项目走独立路线
- 需求澄清：真正的结构化 = 合同实质（金额、付款条件、交货方式等）入库为字段且能链接回原文
- 提出两层机制：第一层为商业交易的基本行为单元，第二层为单元下可设立的细粒度规则
- 目的讨论：完备性（无漏项）、忠实性（无添加）两个不变量确立
- 定位钉死：基础设施性质的底座，只关注对商业世界的法律关系做精细化建模
- 否定两个假问题：合同群（建模对象是带锚的关系，跨合同是消费方的事）、法域（上层按商业认识分类，法域差异只落基层词表）
- 命名定稿：交易单元（unit）/ 规定槽（slot）
- 师承结论：向语言学学工艺（FrameNet 框架-槽、词典学条目作业、术语学治理），向法学与逻辑学学规范结构（Hohfeld 模态、道义逻辑）

## 2026-09-10

- 清空重推建模文件本质：带锚、带来源级的静态事实库（纠正了早前"主张账本"的过度设计）
- 权利义务关系存储推演：关系原子 =（当事人组；模态；行为类；细节{槽:值}）；事件为连接铰链；救济 = 事件触发的二级关系
- 值形态定为五种（后改四种再加回两种为六种）：量、时、条件、算式（后补名/文本、引用）
- 技术选型定案：CLI + 单个 SQLite 文件，零依赖纯标准库
- 词表存放方案：案件为源、全局为聚合派生；开工拷快照、案件自含
- 词表纪律：不能改只能增删；案内只增、删只在全局聚合
- 词表定为外置"变量"文件（YAML），工具不含内容
- CLI 分两组（案件/词表）、两条桥（开工向下、聚合向上）
- 变量文件格式定案：文本为源（git 治理）、SQLite 为运行快照
- 初始词表生成工序：两遍两闸（宽容生成→人删并定单元→逐单元收割槽→快审）
- 语料定为混编：多机构范本给结构覆盖 + 真实合同给脏乱与非标
- 测试方法定稿：用户供真实合同 → 机器独跑 → LLM 双向逐条核对 + 机械底座 + 种错测核对员
- 第一性原理重推三层结构：主语/关系类/细节；词表 = 抽掉主语的三层结构

## 2026-09-11（上半日）

- 外部评审（review-principles.md）五条 A 级意见全部核验成立
- **A1 解决**：合同成为第五类节点；元规定 = 以合同为主语、带锚的记录（生效条件、文件构成、文本型定义、解释规则、除外双指针）；单元判据推广——主语可为当事人或合同
- **A2 解决**：完备性诚实分层（条款级机械保证 + 断言级 LLM 核对员）；对账加第五查"归类覆盖"（双向）
- **A3 解决**：值形态四种→六种（补名/文本、引用）；条件升级为布尔表达式；单位表归工具自带配置文件（标准出生 vs 归纳出生分流判据）
- **A4/A5 解决**：项目目的重述为"针对某特定合同做精确建模"；角色/事件类/基准三张类级清单不建（跨合同用途出目的）；跨案边界写死（跨合同数据查询归消费方）；案件边界判据补定（正文+组成部分+从属文书）；出身表补格式版本
- 主体识别机制重设计：识别内嵌于提取（填当事人组即完成指称判定）；主体 = 独立 id 节点（规范形+别名集）；③级指称绑定；事件带参与者引用；对账加第六查"称谓闭合"
- 同一性核查 = 比 id 相等（下游读者不需要穿别名集做运行时归一）

## 2026-09-11（下半日）

- **概念大清理**：废除池（待归类容器）、认定（人机交互步骤）、"池→认定→晋升"通道——所有信息点必须归类，不存在待定去处
- 缺口表新增：归类层缺口的库内存放处（写入即定、只读、无状态流转，非池的复活）
- 词表出生通道收紧：槽与单元均不可案内新造——词表出生只有一个通道（全局、律师、经词表工具）；案件快照开工即冻结
- **B1 关闭**：当事人组 =（主体 id + 性质）引用；性质两层暂定——核心八种随模态封闭（义务人/受领人、行使方/承受方、享有方/相对方、受保护方/受限方），功能参与方开放按文
- **核查机制废除**：核对 skill 与核对员整个出局（后续种错、换模型、身份复核等均为过度设计）；测试方法重写为"机器独跑→机械六查→考卷→数字"；交付物六件变五件
- **B3 关闭**：模态升为机械可验（情态词映射表封闭在代码）；"按级过滤"承诺收窄为管值与模态
- **B2 关闭与修改链建立**：修改 = 新建完整新记录（未改槽连值带锚承袭）+ 引用表修改边连接新旧
- **锚机制定形**：概念设计中不出现数字——锚 = 引文 + 条款地址（与法律文书引用原文同构）；验证 = 引文在该条款内逐字可搜得
- 入库切分参照 contract_v3：复用 scan_structure（纯脚本、stdlib），四项适配（直接消费条款清单、重复编号消歧、无编号段入缺口表、扫描异常入缺口表）
