# 初读：连续分段阅读与统一归纳

初读在登记、完整条款切分之后，打标和分组之前。交付案件概要、有原文依据的主体与事件，以及实际阅读和问题处置记录。覆盖本轮全部已提供材料，包括前言、article、标题区域、签署、表格和附件。完整关系和槽值提取仍由后续任务完成；preparation 的 `covered_clauses=[]`。

本说明随安装交付，执行不依赖仓库 docs。写入格式见本文件真实位置的 [data-formats.md](../../../references/data-formats.md)，工具参数见 [case-cli.md](../../../references/case-cli.md)，正式关系任务交接见 [handoff.md](handoff.md)。

## 1. 主会话：固定版本并准备全部材料

用现有 query 读完全部分页，取得素材、当前文本、完整条款、冻结词表，以及已有概要、正式主体和事件。固定 case_id、素材/文本对象及记录版本、条款对象及记录版本和提交序号。各素材内部按 `sequence` 排列，不能用 query 默认返回顺序；多素材保留各自身份和顺序，登记先后不表示法律优先顺位。

全文目录至少列素材名称、原编号或区域位置、对象/记录版本、sequence、Unicode 字符长度和原文位置/入口。无标题用原编号或区域位置，不要求模型先读正文发明标题。区分已提供与仅引用的材料；未提供引用由实际阅读记录补充。

### 连续分段

每任务目标正文量初值 **20,000 个 Unicode 字符**，可按模型和工具能力调整。每份素材按顺序累积完整条款；加入下一条将超目标时，在该条之前结束当前段。素材之间不拼成一个连续段。前言、签署、章节引言和附件区域也参与分配。

单条自身超目标时，独立交给一个读手，可分连续窗口读完；不拆正式条款，不让多个读手各自认定其一部分。各段主读范围两两不交，并集等于本轮范围；理解上下文可重复读取。切分错误走既有修正规则，不能在初读分段时掩盖。

任务数量由篇幅/条款边界决定，同时运行数量由宿主并发控制，不另设 scout。多段交分段读手并行阅读，再由**一个归纳读手**统一认定；只有一段时同一读手兼任归纳，不另开 agent 重读自己的产物。

### 派发前准备完毕

每个分段任务提供：

- 本说明、角色、主读范围、独立输出路径。
- 全文目录及材料清单。
- 本段逐字原文、条款/版本/位置对应，上级标题作为阅读上下文。
- 全文可定位读取入口，用于明确问题的跨段回读。
- 已有概要、正式主体和事件的完整查询，空结果也明确保存。
- 完整冻结词表和正式数据格式；初读不按词表过滤信息。

可同时给机器索引和简洁正文，管理标题与原文块分开，原文逐字保留。不让每个读手重复分页导出全库、扫描结构或寻找原件。预列连续阅读窗口及位置；窗口大小按宿主单次输出能力设置，与任务篇幅参数分别处理。输出截断必须补读，调用成功不等于读完。

内部辅助和参数见 [reading-inputs.md](reading-inputs.md)。所有引用按说明文件真实位置解析；派发前检查实际路径，不复制出失效相对引用。

## 2. 分段读手：全读并记原文依据

读说明、全文目录和本段范围，然后按窗口顺序读完正文；第一次阅读不能以关键词检索代替。随读记录，不依赖其他并行读手未完成的输出。跨段引用先记目标和问题，妨碍本段理解时定向补读，一般归并交归纳读手。已解决问题可复用带出处的笔记，新问题仍可再次回读。

笔记采用 Markdown，不建立严格业务 schema；各读手只写分配的独立文件。初值未读/未核对，实际处理后再填结论。

| 章节 | 内容 |
|---|---|
| 阅读范围 | 素材、文本、条款版本；实际读过的窗口/范围；截断、未读、受阻范围明确列出 |
| 本段概况 | 每条款或自然区域主要规定，复杂条款保留多个要点 |
| 主体、对象与组织方式 | 原文称谓、身份、角色、项目、包、批次/阶段及适用范围，不自动合并近似名称 |
| 定义与共同限定 | 共同前提、例外、包独立性、文件范围及适用对象 |
| 条件与时间联系 | 连续原句、相关共同前提、参与者、对象、包/阶段及出处 |
| 跨段引用与问题 | 目标、具体问题、是否补读及依据；材料缺失与原文歧义分别记录 |

每项事实或线索至少标条款记录版本及原文片段，可附字符位置。原编号不能成为唯一定位。概况可简短；用于正式主体/事件的依据必须能准确回到原文。

条件与时间联系保留足够的连续原文，必要时留前置总句、完整列项或多处独立引文。与/或、对应包、例外、时间修饰和共同前提不得丢失，不能只记一个事件名称。例如“检测完成后三日内出报告，报告送达后五日内付款”保留完整句及三日/五日各自所指，交归纳读手认定不同事项。

未来实际数值未知、合同明确空栏、引用材料未提供、转换损坏和本段尚未找到分别描述，不补造事实或假 null。只读一段不能断言全文不存在，不假定合同事项已实际发生。

分段读手不建正式事件表、不分配事件 ID、不裁决跨段同一性。返回笔记路径、实际已读范围、未读/受阻范围和待归纳问题摘要。笔记存在或无异常不能代替读完；截断补读后更新范围。

## 3. 一个归纳读手：全局认识及统一认定

输入全部段内记录、固定原文/目录、材料清单、既有概要及正式主体/事件、冻结词表、数据格式和 preparation 输出路径。单段由原读手继续。

1. **确认收齐。** 检查实际主读范围、未读和截断声明；缺文件、未读或依据不足交回补齐，不能推断无重要内容。
2. **建立整体结构。** 整理主体、角色、交易对象、包/阶段、材料组成及共同定义。
3. **处理跨段关联。** 称谓共指、包归属、定义引用、共同限定逐项处理；定向回读，必要时退回读手补充。
4. **统一认定主体与事件。** 按原文判断粒度、身份、同一性，复用既有正式记录。主体先确定或与依赖事件同批建立。
5. **写概要及一个 preparation JSON。** 正式断言依据回到原文锚，摘录不足先回读。笔记不能作正式记录的来源前提。

“验收合格且收到发票”是两个事项，逻辑组合属具体条件；“交付后十日”与“交付后三十日”复用同一交付事项，偏移属具体时间。保留使用联系与依据供后续提取。

名称相同不等于同一事件。两包同名证书、报告送达与签发、技术支持完成与据此发证须分别判断；保留共同前提、包/阶段、参与者和来源，区分知悉与事实发生。不明同一性不自动合并，保留可支持描述和歧义，不填造身份信息。前言/签署中有明确角色的代表也纳入主体准备。

每次回读记录具体问题、目标条款、结论和依据，结论可为找到依据、材料未提供、原文歧义或需要补读。笔记足够不要求全篇重读；不足补相应段，涉及大量正文可扩大范围并说明原因。不设调用次数上限或独立审核 agent/互查关卡。

## 4. 概要及正式提交

概要 body 按实际内容使用六个栏目：

1. **材料范围**：已提供素材/文本版本、仅引用材料及转换问题。
2. **主体与称谓**：签约方、角色、明确代表及重要称谓对应。
3. **交易及履行结构**：标的、包/项目、阶段及独立/共同安排。
4. **关键安排**：价款组织、付款/交付结构、验收和支持/保修，重要数字附所指对象，不确定保留问题。
5. **共同定义与限定**：理解局部条款所需内容和原文位置。
6. **未解决事项**：歧义、缺失、不可读内容及其影响。

概要是背景，不承担证据功能。后续仍读负责条款及相关上下文。概要事项可带原文位置，不要求 CLI 分配 ID 前预填事件 UUID；正式事件写入后完整交接。

输出一个现有 `phase=preparation` JSON，`covered_clauses=[]`，可带 `overview:{text_versions,body,authored_by}`；records 包含有依据的主体、event、anchor 和必要 reference。同批引用用 local_id，既有业务对象用 object_id，固定版本按数据格式用 record_id。定义先服务理解，不把全部定义值前移为本阶段强制交付。

笔记不逐份入库。主会话执行一次已有 write，失败将具体错误及必要版本交归纳读手修正，成功保存完整回执；读手不直接改数据库。然后读全部分页的概要、事件和共用对象，保留 data、object_id/record_id、evidence、provenance，不将 description/participants/包阶段缩成 ID/name 简表，空事件清单显式交接。

## 5. 文件位置、恢复和完成

目录、原文、任务、笔记、归纳及问题记录放合同 tasks；preparation/修正放 submissions；CLI 回执放 receipts；写入后查询交接放 reports。按现有序号分配独立文件，不覆盖旧材料，不新增状态库，工作文件未写入不能冒充正式 ID。

中断时查询库/回执；对应版本一致的完成笔记复用，只续做未完成范围。部分文件保留已读/未读声明，不因存在判完成。归纳失败复用有效笔记；已有成功提交按重放/追加规则处理，不重复建同义对象。

增量主读新材料，供给既有概要、主体与事件，对受影响旧定义/共同条件定向回读。登记较晚不等于覆盖旧规定；文本或条款范围改变则重定受影响依据，不能沿用失去版本对应的完成说明。

全部主读范围实际读全、无未解释截断；已发现跨段问题有明确处置；概要完成且主体/事件有依据；preparation 写入成功并可完整查询，才交接准备完成。缺失、损坏或歧义不能伪装解决；材料质量妨碍建模时按既有异常规则处置。

机械辅助只查范围、文件、版本、路径和格式，不能证明语义无遗漏；主会话收范围和文件，合同含义交归纳读手。完整合同的双向语义验收继续适用，初读完成不产生完整提取完成声明，也不向关系读手增加补提所有事件职责。
