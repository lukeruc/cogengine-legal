# 初读：连续分段阅读与统一归纳

初读在登记、完整条款切分之后，打标和分组之前。交付案件概要、有原文依据的主体与事件，以及实际阅读和问题处置记录。覆盖本轮全部已提供材料，包括前言、article、标题区域、签署、表格和附件。完整关系和槽值提取仍由后续任务完成；preparation 的 `covered_clauses=[]`。

本说明随安装交付，执行不依赖仓库 docs。写入格式见本文件真实位置的 [data-formats.md](../../../references/data-formats.md)，本说明 §2 给 reader、§3—§4 给 summarizer，data-formats 在构造正式记录时按需查相应章节；派发正文含对应模板的完整固定部分。§1、§5 中的材料导出、正式写入和恢复由主会话执行，不授予子任务同等操作权限。

## 1. 主会话：固定版本并准备全部材料

主会话调用 `prepare_task.py reading`，由辅助程序使用现有 query 收齐全部分页，取得素材、当前文本、完整条款、冻结词表，以及已有概要、正式主体和事件，固定 case_id、素材/文本对象及记录版本、条款对象及记录版本和提交序号。主会话无需先手工导出同一批快照。各素材内部按 `sequence` 排列，不能用 query 默认返回顺序；多素材保留各自身份和顺序，登记先后不表示法律优先顺位。

全文目录至少列素材名称、原编号或区域位置、对象/记录版本、sequence、Unicode 字符长度和原文位置/入口。无标题用原编号或区域位置，不要求模型先读正文发明标题。区分已提供与仅引用的材料；未提供引用由实际阅读记录补充。

### 连续分段

每任务目标正文量初值 **20,000 个 Unicode 字符**，可按模型和工具能力调整。每份素材按顺序累积完整条款；加入下一条将超目标时，在该条之前结束当前段。素材之间不拼成一个连续段。前言、签署、章节引言和附件区域也参与分配。

单条自身超目标时，独立交给一个 reader，可分连续窗口读完；不拆正式条款，不让多个 reader 各自认定其一部分。各段主读范围两两不交，并集等于本轮范围；理解上下文可重复读取。切分错误走既有修正规则，不能在初读分段时掩盖。

任务数量由篇幅/条款边界决定，同时运行数量由宿主并发控制。多段交 reader 并行阅读，再由**两个 summarizer 分工**统一认定；只有一段时原 reader 接续主体/事件，另派概要 summarizer，不另开主体/事件任务重读自己的产物。

### 按角色准备输入

主会话通过 prepare_task reading 导出 v2 manifest、reader task 及三部分 instructions；reader 正常只读指定完整原文窗口、简明目录、必要上级上下文和直接交付的笔记栏目。机器 manifest、词表、空共享查询和完整格式不进入 reader 输入；不会因安装资源可取得而要求通读。主会话总体说明在初读前形成，不预设合同架构。

固定原文、管理身份及完整查询保存在合同 tasks，供主会话或实际使用者；程序快照不等于模型必读。上下文和回读入口逐文件授权，截断补读；目录只说明文本排列。参数及恢复见 reading-inputs.md。

`reading` 所需 `preparation_files.records/overview` 是主会话预定的两份 `submissions/*.json` 路径，文件须尚不存在；后续 summarizer 通过构造工具生成它们。安装模板由程序自动读取，不作为该参数输入。完整字段表和可替换示例见 [reading-inputs.md §1](reading-inputs.md#1-reading准备初读任务)。

## 2. reader：全读并记原文依据

读说明、全文目录和本段范围，然后按窗口顺序读完正文；第一次阅读不能以关键词检索代替。随读记录，不依赖其他并行 reader 未完成的输出。跨段引用先记目标和问题，妨碍本段理解时定向补读，一般归并交 summarizer。已解决问题可复用带出处的笔记，新问题仍可再次回读。

笔记采用 Markdown，不建立严格业务 schema；各 reader 只写分配的独立文件。初值未读/未核对，实际处理后再填结论。

| 章节 | 内容 |
|---|---|
| 阅读范围 | 素材、文本、条款版本；实际读过的窗口/范围；截断、未读、受阻范围明确列出 |
| 本段概况 | 每条款或自然区域主要规定，复杂条款保留多个要点 |
| 主体、对象与组织方式 | 原文称谓、身份、角色、项目、包、批次/阶段及适用范围，不自动合并近似名称 |
| 定义与共同限定 | 共同前提、例外、包独立性、文件范围及适用对象 |
| 条件与时间联系 | 连续原句、相关共同前提、参与者、对象、包/阶段及出处 |
| 跨段引用与问题 | 目标、具体问题、是否补读及依据；材料缺失与原文歧义分别记录 |

每项事实或线索至少标条款记录版本及原文片段，可附字符位置。原编号不能成为唯一定位。概况可简短；用于正式主体/事件的依据必须能准确回到原文。

条件与时间联系保留足够的连续原文，必要时留前置总句、完整列项或多处独立引文。与/或、对应包、例外、时间修饰和共同前提不得丢失，不能只记一个事件名称。例如“检测完成后三日内出报告，报告送达后五日内付款”保留完整句及三日/五日各自所指，交 summarizer 认定不同事项。

未来实际数值未知、合同明确空栏、引用材料未提供、转换损坏和本段尚未找到分别描述，不补造事实或假 null。只读一段不能断言全文不存在，不假定合同事项已实际发生。

reader 不建正式事件表、不分配事件 ID、不裁决跨段同一性。返回笔记路径、实际已读范围、未读/受阻范围和待归纳问题摘要。笔记存在或无异常不能代替读完；截断补读后更新范围。

## 3. summarizer：主体与事件

输入同批笔记、目录和固定原文回读入口、完整既有身份及本角色适用来源/记录规则。单段原 reader 接续。本任务不写概要，不读另一个任务并行中间产物。

1. **确认收齐。** 承接主会话实际执行的文件/版本核验和 reader 范围回报，按指定路径逐份先读范围声明再读正文；比较实际主读范围、未读/截断声明和可见矛盾。正常不重复 ls/wc、打印整个 manifest 或探测快照键；异常/恢复仅核对受影响对象并说明原因。缺文件、未读或依据不足交回补齐，不能推断无重要内容。
2. **建立整体结构。** 整理主体、角色、交易对象、包/阶段、材料组成及共同定义。
3. **处理跨段关联。** 称谓共指、包归属、定义引用、共同限定逐项处理；定向回读，必要时退回 reader 补充。
4. **统一认定主体与事件。** 从笔记中的条件/时间原句及实际使用位置判断粒度、身份、同一性，核对包/阶段、参与者及引用所指，复用既有正式记录。主体先确定或与依赖事件同批建立。
5. **写不含 overview 的 preparation 记录提交。** 正式断言依据回到原文锚，摘录不足先回读。笔记不能作正式记录的来源前提。

“验收合格且收到发票”是两个事项，逻辑组合属具体条件；“交付后十日”与“交付后三十日”复用同一交付事项，偏移属具体时间。保留使用联系与依据供后续提取。

名称相同不等于同一事件。两包同名证书、报告送达与签发、技术支持完成与据此发证须分别判断；保留共同前提、包/阶段、参与者和来源，区分知悉与事实发生。不明同一性不自动合并，保留可支持描述和歧义，不填造身份信息。前言/签署中有明确角色的代表也纳入主体准备。

### 按原文使用位置核对事件与来源

在形成同一份preparation时由本 summarizer 完成以下判断，不增加事件使用表或独立审核步骤：

- “收到有效发票后30日付款”的基准是相应包/阶段的发票收讫事项。月度报告、审核、开票、收讫和付款不是一个起算时点，不能把付款输出自身合进基准事件；时间偏移留在后续时间值。
- 同一事项多处作为基准可复用事件，不要求每句话建节点，也不按事件数量判断完整性。需要区分的发生事项按其具体使用位置认定，不能仅以某条款的整段程序名称概括。
- Date与Certificate、签发与收到、正式接收与视同接收分别按原文判断。不足以确认同一时保留区别、原句及疑义；不能在概要里说“疑指”，正式事件或引用却静默写成确定同一。
- description、participants等每项实质内容须有实际支持的原文来源。不要把整段程序和后果全部抄进事件，再用一个介绍句作为全部断言依据；笔记和概要不是正式来源前提，必要时定向回读补原句。

例如不同条款分别以接收Date和Certificate起算，合同又允许视同接收或延迟发证，不能仅因名称近似就称两种基准“同旨”。保留原文差异与影响，不替合同默选解释。

每次回读记录具体问题、目标条款、结论和依据，结论可为找到依据、材料未提供、原文歧义或需要补读。足够的逐字摘录及固定条款版本可直接建原文锚，不要求每条正式断言都重新打开原文。笔记足够不要求全篇重读；不足补相应段，涉及大量正文可扩大范围并说明原因。不设调用次数上限或独立审核 agent/互查关卡。

## 4. 概要及正式提交

概要 body 按实际内容使用六个栏目：

1. **材料范围**：已提供素材/文本版本、仅引用材料及转换问题。
2. **主体与称谓**：签约方、角色、明确代表及重要称谓对应。
3. **交易及履行结构**：标的、包/项目、阶段及独立/共同安排。
4. **关键安排**：价款组织、付款/交付结构、验收和支持/保修，重要数字附所指对象，不确定保留问题。
5. **共同定义与限定**：理解局部条款所需内容和原文位置。
6. **未解决事项**：歧义、缺失、不可读内容及其影响。

概要是背景，不承担证据功能。后续仍读负责条款及相关上下文。概要事项可带原文位置，不要求 CLI 分配 ID 前预填事件 UUID；正式事件写入后完整交接。

概要职责由第二个 summarizer 独立承担：读同批笔记、目录/材料范围和授权原文，用原文称谓形成上述六栏目；不建正式对象、不分配 ID、不裁决身份合并，也不等待另一任务的新 ID。只交 body 与显式 issues，通过绑定生成 records=[]、含 overview 的 preparation。

两个任务由主会话用 synthesis 固定辅助同时准备；各自只输出一类成果，不重复另写概要。记录任务以 complete_task 生成不含 overview 的 preparation；概要任务只用正文及 issues，不需要完整业务 schema 或锚工具。均 covered_clauses=[]，文件不是完整提取完成声明。

主会话独立 write 两份并保留回执，次序不限；失败仅回原任务修正，成功部分不回滚或重复建对象。接收明确冲突，身份问题交记录任务、表述问题交概要任务，补交必要原文，不新增全量互查或仲裁 agent。两份都成功、真实阅读覆盖完整且影响交接的问题已处置后，查询正式概要正文直接作 tagger/extractor 背景，正式身份完整交接。旧概要不代替本轮产出。

## 5. 文件位置、恢复和完成

目录、原文、任务、笔记、归纳及问题记录放合同 tasks；preparation/修正放 submissions；CLI 回执放 receipts；写入后查询交接放 reports。按现有序号分配独立文件，不覆盖旧材料，不新增状态库，工作文件未写入不能冒充正式 ID。

中断时查询库/回执；对应版本一致的完成笔记复用，只续做未完成范围。部分文件保留已读/未读声明，不因存在判完成。单份归纳失败复用有效笔记，仅修失败部分；已有成功提交按重放/追加规则处理，不重复建同义对象。

增量主读新材料，供给既有概要、主体与事件，对受影响旧定义/共同条件定向回读。登记较晚不等于覆盖旧规定；文本或条款范围改变则重定受影响依据，不能沿用失去版本对应的完成说明。

全部主读范围实际读全、无未解释截断；已发现跨段问题有明确处置；概要完成且主体/事件有依据；两份 preparation 均写入成功并可完整查询，才交接准备完成。缺失、损坏或歧义不能伪装解决；材料质量妨碍建模时按既有异常规则处置。

机械辅助只查范围、文件、版本、路径和格式，不能证明语义无遗漏；主会话收范围和文件，合同含义交 summarizer。完整合同的双向语义验收继续适用，初读完成不产生完整提取完成声明，也不向 extractor 增加补提所有事件职责。

主会话在派发正文交接 case_id、词表哈希、素材/文本/条款固定版本和共享查询序号的依据，每段笔记路径及实际已读/未读/截断回报、已检查项目和仍有问题、分配的输出位置；不新增核验 JSON 或阅读状态库，未执行检查不能称通过。导出只查文件和版本，不能证明已读或语义完整。manifest 的初始 unread 不是 reader 最新状态。精确引句匹配交 find_quote，不为纯字符串验证重读整条原文。
